# Durable transcript coverage

`transcript.js` (Pi sessions), `claude-transcript.js` (the Claude Code primary session) and `supervision.js` (fleet outcomes) are read-only adapters. No pane scraping, thinking generation, prompt changes or extra mirror traffic is required.

## Sources and confinement

- Metadata inventories cover `FM_HOME/state/branch-session/*.jsonl` and optional `state/main-session/*.jsonl`.
- `state/.branch-session` and optional `.main-session` point to JSONL inside the same real home. Duplicate paths load once.
- `state/.branch-mirror-cursor` contains `{file,index}`. The writer cursor index is not a read-history limit. An external main Pi directory is allowed only when its basename encodes the exact selected home (synthetic example: `--synthetic-home--` for `/synthetic/home`), with no directory symlink. Each regular JSONL file must have a first session record whose `cwd` equals the real selected home. Other homes are never scanned. Browser labels use `main-pi-session/<filename>`, not the absolute path.
- A Claude Code primary is read from `<CLAUDE_CONFIG_DIR or ~/.claude>/projects/<home with every non-alphanumeric character replaced by "-">/`, never another directory. The session id in `state/.lock-session` selects `<id>.jsonl`; without a valid sidecar the newest file whose first record is not a queued Firstmate wake/mirror envelope is used and the note says it was inferred. Symlinked directories or files are not followed. Browser labels use `claude-main-session/<filename>`. User prompts (including human-flagged and queued prompts and slash commands) map to unverified session input; assistant text and native non-empty thinking map to the shared model; tool calls/results are tools; hook/background notifications, local command output and interrupts are harness; meta/skill bodies, compaction summaries, sidechains, system-reminder text, Stop-hook wakes and attachments other than human queued prompts are omitted.
- `state/branch-outcomes.jsonl` non-silent `{seq,task,summary,verdict,epoch}` records become fleet notes with recorded epoch time. Optional `terminal-outcomes.jsonl` also supports `task_id` and `created_epoch`. Notes go to General and the metadata-owned project lane. The ledger wins over duplicate displayed merge notices.
- Captain inbox notes, task status, task inbox and outbox remain separate sources. Task inboxes are internal steers, not captain chat. Presentation receipts are not original dialogue.

## Authorship

The Captain identity is a trust boundary: never show unsent text as the captain's. `authorship.js` owns the classification for the transcript adapter, captain inbox notes and chat asks; lane routing does not depend on it.

- **Captain** is granted only to an authoritative explicit-send record: a Quarterdeck send that Firstmate's guarded `fm-inbox.sh note --request-id` path saved. The note must be a `.note` in `state/inbox/` or `state/inbox/handled/` under its own `id`; its `request_id` must be in a Quarterdeck send namespace and agree with the Quarterdeck envelope in its body (`agentos-review:<batch>` with the `fm-review` batch or legacy review header, `quarterdeck-call:<uuid>` with an `fm-bearings-answer` envelope on `channel:"quarterdeck"`, `quarterdeck-thread:<key>:<uuid>` with an `fm-quarterdeck-thread` envelope naming that request id); and Firstmate's request reservation `state/inbox/.requests/<request_id>` must name that note id. Review batches, Captain's Call answers and card-thread notes all meet this, pending or acknowledged, and a confirmed send reloads an open Fleet Chats log (or marks it behind until Fleet Chats opens again) so the captain's message appears.
- **Unverified input** (`role:"input"`, kind `input`, labelled *unverified input*) is everything else that could look like the captain: Pi and Claude `role=user` entries (including Claude `origin.kind:"human"` and queued prompts, which injected terminal text shares), `[captain]` mirror records, branch-session input, and any other captain inbox note, including agent-written notes, notes with an `author=` header and anything in the legacy `inbox/`. Authors read *Pi session input*, *Claude session input* or *Inbox note*; text, timestamps, sources and record IDs are kept. It is never relabelled Firstmate and is off by default; select **unverified input** under Message kinds to inspect it. It never resolves a chat ask.
- An LLM role, a content prefix such as `Captain:` or `[captain]`, a lane marker, a filename or presence in an inbox proves nothing. Old records are not upgraded retrospectively.

Missing, invalid or unavailable main sources produce explicit gap notes, never reconstructed conversation. A different storage convention needs a deliberately reviewed adapter or an authorized mirror preserving original role, native thinking, timestamps and identity. Do not broaden discovery to arbitrary session directories.

## Bounded display contract

The [source window](SESSION-WINDOW.md) loads active/recent sources initially, with older metadata and explicit bounded loads. Within selected sources, records are read line-by-line without per-kind/status-line caps. A source larger than the window loads only its newest whole records (the partial leading record is dropped) and the coverage lists a warning that older history in that source is not shown; windowed and Claude records use byte-offset record IDs so appends keep IDs stable. Invalid JSON and undated conversation records are counted as coverage limits rather than assigned invented clocks. The client renders at most 200 records per page and distinguishes loaded records from the current page.

Complete standalone `[fm-lane <registered project>]` / `[end <same project>]` blocks route exclusively to that project before legacy name matching. Multiple valid blocks separated by blank lines project independently with distinct derived record IDs; original Pi/Claude text is unchanged. Theme-suffixed labels (for example `Example-Store-UI`) resolve to the longest registered parent followed by a hyphen, for single- and multi-block replies alike. Exact registered names take precedence over registered-parent prefixes; registered ownership wins before compatibility aliases. This prevents a historical product registration's alias from claiming the current product's explicit label. Unknown/ambiguous parents fall back conservatively. Valid single-theme envelopes route exclusively to their declared parent even when the body mentions other projects. Public product aliases `Quarterdeck` / `Quarterdeck` and `Lavish` resolve to `fm-quarterdeck` and `lavish-axi`. Explicit General stays only in General. General receives no project-block copy. Multi-block projections additionally carry the original record ID/text and ordered, resolved blocks as display context (`mixedLaneMessage`); routing and projected identities are unchanged. Fleet Chats merges selected projections into one original reply. With fleet filtering active, selected blocks start expanded and other blocks remain available behind compact lane/preview/line-count sections. The visible `[fm-lane Name]` marker itself is the button, replacing (not duplicating) the plain marker in the message. Preview and line count appear only when collapsed. All starts with every block expanded. Buttons support native keyboard activation and expose `aria-expanded`/`aria-controls`; disclosure choices last only in the open tab and are scoped to the fleet selection. Single-block messages retain their plain rendering without disclosure controls. Search includes the original reply, including collapsed context; annotations target its original durable record. Unknown/malformed/unmarked envelopes use legacy ownership/name matching, which is not perfect contextual attribution. Lane, task and disk-session filters intersect.

Captain, Firstmate replies and supervision notes default on. Native thinking enables thinking when present; crew, tools, harness, steers, branch replies and unverified input default off. Main mirrors are Firstmate replies, not crew replies. Thinking is only native stored assistant content. Tool calls/results and shell output use the tool class. Pure harness operation envelopes, wake prompts and skill dumps are omitted; other user text and mixed ordinary/skill blocks survive as unverified input.

Native main turns supersede same-role/kind/text mirrors within 60 seconds; duplicate branch mirrors in that window also collapse. Genuine repeated turns elsewhere remain. Stable record IDs deduplicate cross-lane appearances. Markdown/raw views escape HTML; lane markers remain visible text. Images get unsupported-attachment labels. Unpersisted text cannot be recovered.

The main desktop Fleet Chats header groups **Compact**, **Last viewed** and **Latest** with the title, search, text size and paging controls, without a separate reading bar. At narrow desktop widths reading and paging move into a labelled **Reading and paging options** button/dialog with `aria-expanded`, native modal focus and Escape dismissal; title, search, text size and diagnostics stay in the header. The shell owns same-node placement across both alternatives; no hidden duplicate or positive tabindex is used. On phones the same reading controls live in **Fleet Chat options**, opened by tapping the top conversation title. Controls retain labels, accessible descriptions, 44px targets and Compact's pressed/active state. It shows one line per message with recorded time, sender, message kind and a short preview. Mixed-lane messages show one such line per existing lane block, including the lane name. Clicking a compact line switches the entire view back to full messages, expands lane blocks and native thinking/tool disclosures, and preserves the clicked line/message's viewport position (within scroll bounds). Switching off Compact from the toolbar preserves existing inner lane choices instead. Mode persists per fleet/filter view in `fm-agentos-compact-views.v1` (up to 60 compact views), with tab-memory fallback if storage is denied. Search, record identities, paging and annotation targets remain unchanged. Captain lines have a distinct warm background/border (with sender/kind labels retained, not color alone). Expanding a compact line outlines the entire clicked message with a clear box, retained through automatic refresh until the next click outside that message; clicking inside it keeps the box. There is no date-group collapse.

Each **Message kinds** row has Previous/Next arrows outside its checkbox label, with accessible kind-specific names and 44px phone targets. They navigate strictly before/after the first viewport-intersecting record, across loaded 200-record pages, respecting fleet/kind/search/source filters. Destinations are focused, briefly highlighted and revealed; a jump from Compact expands the full view, while an already-full view expands only the target's collapsed lanes or native details. On phones the options sheet closes to reveal the destination. Unselected/absent kinds and exhausted directions disable their arrows. Previous can explicitly widen a windowed source through the existing 1→2→4→8 MiB limit when no earlier loaded match exists, following stable record identity and stopping at the first match or limit. Changed filters/views cancel pending navigation; loading failures/non-progress do not invent a destination. Older task/disk sessions still use their separate source controls; no automatic archive scan or larger first load is introduced.

**Last viewed** appears beside **Latest** in the desktop header/phone options, enabled when a saved message is earlier than the current viewport. Its disabled state includes a title and first-use hint explaining that leaving Chats or switching browser tabs saves a position. Leaving Fleet Chats, changing fleet/filter views, hiding the browser tab or losing window focus saves the last fully visible message; if none fits, it saves the first intersecting message (for replies taller than the pane). Returning is explicit, not automatic: the control opens the loaded page containing that durable message, focuses it and highlights it briefly without changing lane disclosures. Fleet selection, reported status, message kinds, task, disk source and normalized search each scope the checkpoint; page and text-format choices do not. Up to 60 view checkpoints persist in this browser's local storage under `fm-agentos-last-viewed.v1`, using rendered record keys, not message bodies. Storage denial falls back to this tab's memory. Filtered-out or no-longer-loaded messages disable the control; loading the relevant older history can enable it again. Refresh and scrolling do not overwrite a checkpoint. Both reading jumps preserve Compact/full mode; Latest selects the newest loaded page and scrolls to its bottom. This is a reading aid, not a read receipt or acknowledgement.

UI tests use a DOM stub, not a browser layout engine. No live session identifiers or workload captures belong in public documentation.
