# Lane Chat message annotations (Quarterdeck only)

This is a Quarterdeck projection/context addition. It does **not** change default Firstmate message production, identity, ordering, or stock behavior. It is separate from Lane Chat send-time view context.

The original `recordId` from the Lane Chat API identifies transcript parts (`source:line:part` or stable windowed/Claude `source@byteOffset:part`), projected lane blocks (`:block:index`), and fleet outcomes (`source:index`). See `transcript.js`, `server.js` (`projectedBlocks`) and `supervision.js`. Many other Lane Chat records (captain notes, steers, outbox items, status lines) have no original record ID: `publicMessage` does not assign one. In particular, identical repeated status lines share source, mtime and text. Quarterdeck must not present the UI's hashed review address as an original ID.

New batches use `fm-agentos-review.v2`. Each entry is a lavish-shaped prompt: `{prompt, selector, tag, text, target?, record?, label?}`; optional `uid` is accepted but capture omits session-only UIDs and DOM snapshots. `prompt` (1–4000 characters) is the request, `text` (≤240) is the target excerpt, `selector` is ≤512, and accessible `label` is ≤160. Plain notes use `tag:"message"` with empty selector/text. Entry `route` is sent only when different from the batch route; version is batch-only.

Selected text takes precedence, with `tag:"text"` and a `text-range` target carrying selector/commonAncestorSelector, start/end `{selector,path,offset}` boundaries and ≤32-character prefix/suffix context. Table cells carry `table-cell` targets with unambiguous row/column labels. Element selectors count same-tag siblings, stop at `[data-review-id]` or an ID, and use at most five steps. Inside Fleet Chats they are relative to `.message-content`, retaining the clicked paragraph/list item/code element rather than just the message.

Message annotations add `record:{recordId}` for an original ID, otherwise `{source,at,lanes,sha256}`: source and occurredAt come from the rendered page snapshot and sha256 is the first 16 hex characters of SHA-256 over displayed text, computed at selection. No full message body is delivered for a new no-ID target. These contextual fingerprints are **not a unique identity**: identical no-ID status lines can remain indistinguishable. Status projections never include excerpts from a message record. Malformed IDs, extra fields and out-of-bounds targets are rejected.

V1 wire/receipts and exact same-ID retries remain unchanged. Unsent v1 queue entries convert to v2; old quote drafts retain a bounded excerpt and a fingerprint marked `legacy-quote` with unknown time (epoch), never a fabricated source/time. Captured retries and in-flight batches stay in their original schema. Legacy inbox notes are parsed read-only for display; legacy whole-message quotes are reduced to ≤240 characters in the structured browser projection. A malformed note falls back to normal rendering. Raw view, copy and search retain the original body.

V2 inbox notes have a one-line header, numbered prompts and one fenced `json fm-review` block `{review:{schema,batch,route,version,end,preview},prompts:[...]}`. Fleet Chats displays only prompts with native **i** batch / **a** target chips, including keyboard/tap disclosure, metadata search and compact prompt previews. Dedup IDs remain `agentos-review:<batchId>`.

**Quarterdeck send cutoff.** Send Batch atomically captures all currently queued annotations as one immutable payload and batch ID before network delivery. A note queued after that action stays on the active board for a distinct next batch, including while the earlier batch is sending or after it succeeds, fails, or is retried. A failed or uncertain send retains the captured payload for same-ID retry without joining later items; reload restores both identities independently. Rapid repeated sends cannot submit the same captured batch twice. Send and End captures every remaining item in the tab's persisted active board (including recovered drafts), retries any earlier unconfirmed captured identities separately, waits for durable acceptance of every captured item, and only then ends/clears the active board. Failure retains it; items queued after the end cutoff stay on the board for a later batch. Quarterdeck draft item identities deduplicate repeated storage records, **not** separate annotations with equal text; they are never sent as Firstmate record IDs. Receipt, status and intake semantics are unchanged: acceptance is not supervisor completion, and neither the Firstmate message/record identity nor stock Firstmate behavior is modified.

The displayed message list preserves duplicate no-ID rows using an ephemeral per-lane occurrence number for rendering only; the number is never a record ID or delivered annotation context. Old v1 receipts and inbox notes can include full quoted source text; treat all receipts as private review records. New records carry bounded excerpts only. Supervisor status excerpts omit record text and redact credential-like record IDs.
