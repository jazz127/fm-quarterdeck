# Lane Chat message annotations (Quarterdeck only)

This is a Quarterdeck projection/context addition. It does **not** change default Firstmate message production, identity, ordering, or stock behavior. It is separate from Lane Chat send-time view context.

The original `recordId` from the Lane Chat API identifies transcript parts (`source:line:part`), projected lane blocks (`:block:index`), and fleet outcomes (`source:index`). See `transcript.js`, `server.js` (`projectedBlocks`) and `supervision.js`. Many other Lane Chat records (captain notes, steers, outbox items, status lines) have no original record ID: `publicMessage` does not assign one. In particular, identical repeated status lines share source, mtime and text. Quarterdeck must not present the UI's hashed review address as an original ID.

A Lane Chat message annotation is `kind: "lane-message-annotation"`, `region: null`, and a discriminated `target`: `{type:"record",recordId}` when the rendered message has an original ID, otherwise `{type:"quote",time,text,lanes}` with the displayed timestamp, exact displayed text and displayed lane names captured at selection. No sender, body, preview or timestamp is included in ID targets. Quoted targets are contextual evidence, **not a unique identity**: two identical no-ID status lines can remain indistinguishable. The annotation's own `text` remains the authoritative request. Clicks outside a rendered message use the existing generic `{kind:"annotation",region:{id,label}}` contract. Both states persist through the tab draft, POST, local receipt, guarded inbox intake, and retry under the same batch ID; the status projection keeps the quote out of its bounded excerpt. Malformed IDs and extra target metadata are rejected.

**Quarterdeck send cutoff.** Send Batch atomically captures all currently queued annotations as one immutable payload and batch ID before network delivery. A note queued after that action stays on the active board for a distinct next batch, including while the earlier batch is sending or after it succeeds, fails, or is retried. A failed or uncertain send retains the captured payload for same-ID retry without joining later items; reload restores both identities independently. Rapid repeated sends cannot submit the same captured batch twice. Send and End captures every remaining item in the tab's persisted active board (including recovered drafts), retries any earlier unconfirmed captured identities separately, waits for durable acceptance of every captured item, and only then ends/clears the active board. Failure retains it; items queued after the end cutoff stay on the board for a later batch. Quarterdeck draft item identities deduplicate repeated storage records, **not** separate annotations with equal text; they are never sent as Firstmate record IDs. Receipt, status and intake semantics are unchanged: acceptance is not supervisor completion, and neither the Firstmate message/record identity nor stock Firstmate behavior is modified.

The displayed message list preserves duplicate no-ID rows using an ephemeral per-lane occurrence number for rendering only; the number is never a record ID or delivered annotation context. Receipts and inbox notes can include full quoted source text; treat them as private review records. Supervisor status excerpts omit quote text and redact credential-like record IDs.
