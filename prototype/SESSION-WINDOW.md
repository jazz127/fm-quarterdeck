# Lane Chat source windows

The default task window per lane is every session not explicitly done/failed (including blocked, paused and needs-decision), union the two most recently updated sessions, deduplicated. An old active task outside the recent pair remains in the window. Session activity retains the status file mtime even when status events are trimmed or not loaded, while newer recorded task activity can advance it. The task index is metadata-only for older tasks.

The disk window is active pointer files union two latest-mtime files. Disk inventory is metadata-only. Explicit task/disk selections and hash deep links read exact sources on demand without changing source records. Load older adds ten task sessions per lane or two disk files per click, capped at twenty clicks and sixty pinned identities per type. The 200-record rendered page is separate from the source window. Fleet Chats initially asks for the newest 1 MiB of whole records per disk source, with a visible loading status until the first response. When a loaded disk transcript or second-mate status source has omitted records, a visible “Load more records” control doubles the per-source window (2, 4, then 8 MiB), retaining fleet/kind/search/source selections. Search and filters cover loaded records only; the banner and source warnings disclose this. When older history is omitted, the source-window note says “Older history truncated” and remains visible at the 8 MiB maximum; the expansion button then hides. On phones this note stays in Fleet Chat options with the existing source-window controls. Task/status/note/outcome coverage does not follow the expansion control. The source expansion and older-session controls are independent.

Requests reread authoritative sources; there is no cross-home snapshot cache. Legacy `/api/lanes` calls retain their existing schema and 8 MiB source limit. Optional `windowBytes` requests are clamped to 1–8 MiB and use stable source-byte-offset record IDs even after expansion reads a file whole. Optional `format=refs.v1` sends a top-level `messages` table and integer references in each lane's `messages` array; every occurrence and its order is preserved, and the browser rehydrates before applying existing filters and mixed-lane disclosures. Without that exact format, messages stay inline. JSON responses already negotiate gzip; no new persistent cache or storage owner is introduced. Responses overtaken by changed selection are discarded. Identical rendered pages retain message nodes; changed pages preserve disclosures and scroll intent. Lane Chats refresh is independent of Overview and Quota and automatic reads run only while that view is active.

Selected task and disk identities precede retained identities in each sixty-ID request, deduplicated. An unloaded selection gets at most two automatic follow-ups; persistent non-progress stops with a visible Refresh instruction. Explicit refresh/reselection remains available. Metadata, status, legacy notes, outboxes, outcomes and selected transcripts share one request reader: 8 MiB per file, 32 MiB total read bytes, 1 MiB per line, 20,000 lines/records, 20,000 emitted messages and 2,048 file reads. Repeated metadata reads count too; one JSONL record cannot evade the message limit through many content parts. Transcript sources, second-mate status files, task status events and the outcome ledgers are the exception to whole-file reads: each loads at most its newest 8 MiB of whole records and at most the records still left in the request, within the totals less a reserve (8 MiB and 5,000 records) for the whole-file loaders. Within the transcript loader, requested sources precede active sources, then recent sources; outcome ledgers are read after task status events, so a long ledger takes what is left rather than starving lanes. A source left without budget for one whole record is reported not loaded. Every windowed or unloaded source is named in the coverage warnings. Work classification still folds each task status file whole. Line-size validation covers every whole record in the byte window read, after dropping any partial leading record and before record-budget trimming; discarded records do not consume the record budget. Exceeding any other limit, including one oversized record anywhere in that read window, fails the request explicitly without rewriting or silently omitting records. The brief-intent prefix remains independently limited to 16 KiB. External session discovery reads only the bounded first header line; inventory/metadata enumeration and concurrent requests still have costs. Larger archives need a later server cursor/index design; browser pagination does not grant unlimited backend assembly.

## Reproducible acceptance

Use a temporary synthetic home with more sessions than each window, including an old active task, recent completed tasks, and old disk transcripts. Compare default reads, explicit deep links and Load older; assert deduplication, exact source identity, search/filter preservation, and at most 200 rendered records. Tests in `test/server.test.js`, `test/transcript.test.js` and `test/ui.test.js` cover these contracts.

For a separately authorized browser measurement, record the exact clean serving revision, synthetic fixture size, viewport, cold/warm assembly time, JSON/transfer bytes, request duration and client freshness clock. Do not publish measurements or session pointers from an operator's home as product defaults. Consider caching or streaming only after measuring the bounded path; browser rendering and source assembly are separate costs.
