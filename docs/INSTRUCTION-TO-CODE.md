# Instruction-to-code inventory

## Scope and result

This sweep covers the product surfaces in `README.md`, `prototype/` adapters and browser code, `expenses/`, every shipped skill and executable in `skills/` and `scripts/`, and the integration/release/acceptance contracts indexed by `docs/README.md`. It distinguishes **executable behavior**, **producer conventions** and **operator authority**: documenting a schema does not mean an agent has to implement its consumer by hand. Upstream Firstmate contracts below are the dependencies documented by Quarterdeck, not a claim to have audited or changed an installed Firstmate home.

Three modest conversions are included:

1. **Lane syntax:** `scripts/check-lane-envelopes.mjs` checks a complete outgoing message without changing it or guessing its lane.
2. **Note closure:** `scripts/quarterdeck-note-close.mjs` / `prototype/inbox.js:replyAndAckNote` reply, prove the recorded reply, acknowledge, then prove closure; identical retries repair intake rather than repeat the order.
3. **Restart after landing:** `scripts/quarterdeck-watch.mjs` owns a standalone loopback child and replaces it after a clean fast-forward on the explicitly approved branch. No process adoption, shared service restart, Serve mutation or crash-retry loop.

All are **opt-in**, not automatically installed or called by HTTP. Activation, serialization, scope, rollback and verification are in [Firstmate integrations](FIRSTMATE-INTEGRATIONS.md#mechanical-helpers). These helpers change no stock Firstmate files, preferences, persisted namespaces or AGENTS files. The later opt-in [unified integration installer](FIRSTMATE-INTEGRATIONS.md#unified-mechanical-installation) mechanically owns home-local projections, private health JSON and one preference soft-reference; it still changes no tracked Firstmate files. Moving preference/instruction ownership into a repository-local AGENTS file is a separate change, not part of this sweep.

Status below: **code** = already mechanical; **converted** = added here, remaining authority stays explicit; **partial** = code exists but producer/operator steps remain; **instructions** = deliberately retained or requires a separately designed integration.

## Verification and remaining boundaries

`test/instruction-mechanics.test.mjs` covers lane pass/refusal/privacy limits, note receipt sequencing, incomplete/conflicting states, reply/ack failure and identical retries, clean landing/no-op/refusal, checkout drift and failed-stop ordering. `test/quarterdeck-watch-process.test.mjs` uses temporary synthetic Git repositories and loopback listeners to prove a fast-forward creates a new process, parent loss closes the owned child, occupied ports remain untouched, and public/registry/dev launch is refused. Existing inbox, health, ask-hook, identity, transcript and server tests remain regressions for their integrations.

No new UI behavior needs a paint test. Synthetic process evidence is not live maintenance/Serve/harness activation evidence. None of these helpers is active merely because this document exists. In particular:

- Lane validation checks syntax, not intent, registered membership or task ownership.
- Note closure proves reply+ack intake, not successful execution or completion of a deferred task. Use a stable operator-owned `flock` around the helper and exclude competing manual writers for the same note.
- Landing watch proves its listener/child ownership, not remote health, new-code acceptance, a migrated receipt store or an updated preview registry. Verify health/review identity and the private URL separately after landing; keep installed immutable hook/skill pins separate from the watched checkout.
- Arbitrary note execution, hold resolution, merges, publication, account grants, lock theft and takeover of shared services intentionally remain outside these scripts.
