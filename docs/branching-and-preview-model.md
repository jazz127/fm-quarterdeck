# Quarterdeck branch and preview contract

This is the authoritative branch/version contract. Documentation describes policy, never proof of current local refs, remote checkpoints or deployed processes.

## Authority and truth labels

- `main` is rock solid. No commit, ref update, deployment or publication without explicit captain approval. A passing test or a request to review is not approval.
- `uat` replaces the old staging acceptance role. Firstmate may land only complete, review-ready fixes/enhancements explicitly requested and known to the captain, with tests, exact revision and acceptance evidence. It is not a roll-up of experiments. Remote `uat` publication requires explicit captain approval; a local candidate is not publication approval.
- `stg` is the fluid, clearly labeled unaccepted playground: experiments, crew suggestions and review roll-ups. Firstmate may publish clearly experimental remote `stg` checkpoints autonomously; this is not acceptance. Future `uat` changes flow forward to `stg` under a guarded integration; `stg` never flows up automatically.
- Completed `dev/<feature>` must be pushed to exact local/remote equality before it is durably captured, previewable or promoted. A mismatch is not captured, even if locally committed; never equate stopped with uncaptured or running with captured. Remote `dev/<feature>` captures each completed worker result, even when not runnable or accepted. Group related work coherently only by composing new commits while retaining all original source refs and commit identities. Work is *captured* when committed and remotely backed up; *previewable* only when a registered isolated process serves that exact revision and passes health checks; *review-ready* when requested intent, tests, review and browser evidence are complete; *accepted* only after guarded landing into `uat` (or explicitly approved `main`); *archived* after recording disposition and retained source/remote refs. Labels must never be conflated.

## Admission and promotion

Default promotion selects exact feature commits, records their source SHA(s), target base, resulting SHA(s), tests and review receipt; inspect ancestry and diff for unrelated work before applying. Whole-branch promotion is exceptional and requires proving its complete ancestry and diff contain no unrelated lower-tier work. Never wholesale-promote `stg` into `uat` by default. Changes from `uat` are incorporated forward into `stg`, never the reverse by implication. Resolve conflicts with a new reviewed commit; no forced updates, history rewrites, ref deletion or moving `main`. Rollback creates a revert commit after review, preserving audit history; stop serving a failed preview without deleting its branch. Reopen archived work by a fresh branch/composition retaining source refs.

## Migration and remote durability

Recheck exact branch refs, operator-recorded remote checkpoints and deployed process identity at operation time. Preserve rollback source and private data under separate authority; never infer a running service or accepted baseline from prose. A history-free source transfer carries no refs, objects, remotes or old evidence bindings. After separately authorized repository initialization, regenerate bindings against the new clean identity; see [portability](PORTABILITY.md).

## Preview and provenance

A local UAT host sets `FM_DEPLOYMENT_TIER=uat` on its isolated UAT checkout. Without a registry it displays only the UAT identity and exact served SHA. With a registry it provides a stable selector between warm local UAT and pre-provisioned isolated Staging. The registry includes this exact host UAT commit without checkout/port, excludes Main, and never implies Main is running or remote UAT is published. The stable host owns an explicit registry of display names, branches, exact local checkout commit IDs, separate operator-recorded remote checkpoint commit IDs (optional only for `uat`/`stg`), validation labels and pre-provisioned isolated checkouts for Main, UAT, Staging and explicitly allowlisted Development previews. An absent or stopped runtime is shown as such, not as runnable. Each preview process runs from its own checkout with separate mutable data and lifecycle; neither browser-supplied refs nor user-selected lanes are checkout or destination-agent commands. Host gateway accepts only registered IDs, probes health, serves isolated previews under a stable-origin route, preserves hash deep links, and attaches its own registered branch + exact revision to review receipts. Client-supplied provenance is rejected. A registry update requires operator review of the checkout's exact revision, separately recorded remote checkpoint and process identity; changing a branch ref does not silently change an active preview. The host proves local checkout HEAD equals its expected local commit; `uat`/`stg` serve that healthy local revision regardless of remote equality, local-ahead, remote-ahead, divergence, absent remote or unknown relationship. The remote checkpoint is published evidence, never an implicit active fallback. If local fails, show failure and warm Main, not remote under the same identity. Main's remote checkpoint is authoritative: a local mismatch is stale and not previewable. Development requires equality. Comparison uses only already-present commit objects, with read-only Git commands; absent is distinct from unknown (missing objects or indeterminate ancestry). No fetch, merge, reset, switch, push, force or automatic reconciliation occurs because revisions differ. Divergence is normal for local viewing, but deliberate reconciliation is required before publication or promotion. Mark freshness from the last successful health sample and validation label separately from health. The stable gateway must enforce localhost or one exact configured HTTPS Tailscale Serve origin on writes; no Funnel or general public port. Chat goes only to primary Firstmate; annotation remains a separate method/schema and stores route, stable region, batch/receipt ID, timestamp and data-reading time because code SHA cannot identify changing page content. The gateway's `dataReadAt` is the last successful gateway API read for that preview (or `null`), not proof of the exact visual snapshot in a particular tab; receipt `receivedAt` is independently server-stamped. Do not replace existing revision checks with a weaker path.

### Single authoritative launch/resource contract

**Hard cap: warm stable host plus at most one alternate child, with the gateway always available.** On an approved Main host, Main is the host's own running checkout/revision. On a local UAT host, UAT is the host's own revision; do not register or label Main. Neither host is a managed child or an idle-stop target. Deploying this controller to Main still requires explicit captain approval. The gateway can be evaluated in a task-isolated synthetic Main fixture before that promotion; such a fixture is not production Main acceptance.

Selecting a second alternate follows the authorized **serial** policy: validate candidate → **Busy** while the old alternate has requests/delivery or has not reached its idle deadline → old alternate **Idling / Stopped** → candidate **Starting** → exact health → **Ready**, then navigate. Two alternates never overlap. A preflight failure leaves the old child untouched. A runtime failure after retirement leaves warm Main available, navigates the initiating tab to Main, and offers retry plus an explicit restart of the previous registered preview. It does not pretend the old process survived, silently restart it, or delete data. Simultaneous selections deduplicate the same operation; a different selection while one is pending receives Busy, not a competing operation. Main is always selectable. Selecting Main does not cancel another tab's pending start.

#### Operator provisioning (never a browser action)

Use a private, operator-controlled **Linux** preview root with no symlink components; only the controller/operator may write there. Provision clean isolated checkouts at immutable commits **before** registration. The controller never creates a checkout, fetches, switches refs, resets, migrates tiers, or modifies the primary copy. It executes only read-only Git identity/status commands with Git environment overrides removed and optional locks disabled. HEAD must equal the full registered lowercase 40-hex commit and tracked content must be clean. Treat each checkout and all its imported code as trusted operator-reviewed executable code, not a sandbox for untrusted branches; a malicious server can lie about its revision. Do not modify a registered checkout while it is in use. Preserve its ignored mutable data independently of source updates.

Set these variables on the stable host (which continues to bind **127.0.0.1**, normally port 4173):

| Variable | Default / bounds | Meaning |
| --- | --- | --- |
| `FM_PREVIEW_REGISTRY_PATH` | unset | Operator-owned JSON array, loaded once at startup; no runtime browser edits |
| `FM_PREVIEW_ROOT` | unset (launch disabled) | Existing absolute, symlink-free isolated checkout root |
| `FM_PREVIEW_IDLE_MS` | 300000; 1000–1800000 | Idle deadline; the one-second lower bound is for isolated tests, use five minutes in review |
| `FM_PREVIEW_START_MS` | 15000; 100–60000 | Bounded startup/health wait |
| `FM_PREVIEW_STOP_MS` | 3000; 50–10000 | Graceful wait, then one equally bounded forced wait |
| `FM_PREVIEW_PORT_MIN` / `FM_PREVIEW_PORT_MAX` | 43000 / 43031; 1024–65535 | Permitted loopback port interval; default assigned port is its minimum |

Example registry (replace both commit placeholders with verified immutable identities):

```json
[
  {"id":"main","name":"Main","branch":"main","commit":"<stable-host-40-hex-commit>","remoteCheckpoint":"<operator-verified-remote-main-40-hex-commit>","validation":"accepted"},
  {"id":"dev-example","name":"Development: example","branch":"dev/example","commit":"<isolated-checkout-40-hex-commit>","remoteCheckpoint":"<operator-verified-remote-dev-40-hex-commit>","validation":"captured","checkout":"example","port":43000}
]
```

Every nonempty registry must include its exact stable host revision at launch: Main in default mode or UAT with `FM_DEPLOYMENT_TIER=uat` (and no Main entry). Every host process stays pinned to its startup commit, including UAT. A dirty/unprovable checkout or any changed HEAD (including a clean fast-forward) fails closed with 503 until a process restart. Imported backend modules cannot adopt a new serving identity. Update the exact host registry binding deliberately before restarting; other entries and remote checkpoints remain operator snapshots. The stable running revision and authoritative remote Main checkpoint must match before Main is labeled previewable. `remoteCheckpoint` is required for Main and development; UAT/Staging may use null for absent remote evidence. This is an operator snapshot, not a live remote fetch. IDs are `main`, `uat`, `stg`, or `dev-<slug>` with the corresponding exact branch name. `checkout` is a root-relative sequence of simple directory names, never absolute, traversal or symlinked. Omit it (or use null) for captured but unprovisioned work. Optional `port` must fall in the operator's bounded interval. The stable host entry (Main or UAT) accepts neither checkout nor port. Unknown fields, including legacy `url`, shell text and argv, are rejected. Existing URL registries require deliberate operator reprovisioning; independently running alternate processes are not adopted. Provision only the entries you need; neither branch enumeration nor loading every branch is involved.

The only lifecycle write is exact-origin `POST /api/previews/select` with exactly `{"id":"dev-example"}`. Branch, commit, checkout/path, port, command, action and agent destination fields are rejected, as are query arguments. Same-origin writes mean loopback Host + matching HTTP Origin, or the one exact configured HTTPS Tailscale Serve origin; forwarding headers and arbitrary tailnet hostnames confer no authority. No Funnel, firewall opening, public listener, iframe, or second decision ledger.

The fixed repository-owned launch is the host's Node executable running `prototype/preview-child.js`, with `shell:false`, an isolated cwd, explicit loopback port, and a small controller-created environment. It imports that checkout's server only after another immutable checkout proof. Inherited registry, dev-watch and delivery configuration are not passed to previews. HOME, XDG cache/config/data and temporary files live in symlink-checked, per-ID `.agentos-runtime/` directories **outside** source checkouts and survive retirement. This prevents helper state from dirtying source and breaking a later restart. Quota is read once through the stable gateway's existing cached adapter; isolated previews never launch quota/provider account helpers, including on direct loopback quota requests. An IPC listener announcement from the owned child is required, so a pre-existing listener on the port cannot pass startup. Both `/api/health` (`ok:true`, service `fm-quarterdeck`) and `/api/review` (exact registered revision) must pass before Ready or navigation. Proxied reads re-prove health and process identity; neither a label nor a branch tip is running evidence.

#### Use, retirement and crash recovery

GET `/api/previews` reports Stopped, Starting, Ready, Failed, Revision mismatch, Busy and Idling, active local commit, remote published checkpoint or absent, relationship (`equal`, `local-ahead`, `remote-ahead`, `diverged`, `absent`, `unknown`), validation, health, last successful sample/freshness, reason and active-request count, **not** checkout addresses or process internals. Registry polling and startup probes never renew idle. A successful proxied document/API/health interaction renews use at completion. Validated chat/annotation delivery also renews use, including an unconfirmed delivery needing retry. Invalid writes do not. Each proxied request, stream and gateway delivery holds a generation-specific lease; no idle stop occurs until all leases complete. A disconnected proxy releases its lease only after destroying its upstream; a disconnected browser cannot release an ongoing delivery. Open streaming responses and legitimately refreshing tabs may keep their preview Busy indefinitely; there is deliberately no destructive timeout of active work.

After the bounded idle deadline, stop only the exact child started by this controller: compare generation nonce, PID, Linux boot ID/start ticks, cwd and command to fresh `/proc` evidence, then use that live ChildProcess handle for SIGTERM; wait the configured bound, re-prove identity, then at most one SIGKILL and bounded wait. Never kill by name, process group, guessed port owner, or PID from a stale file. No preview checkout, branch, registry entry, receipt, draft or durable data is removed. A cleanup failure blocks alternate launches but does not disable Main or the stable gateway.

The root's private `.agentos-controller/` contains an exclusive owner lock and atomic write-ahead child record (generation, checkout, commit, port, PID and start evidence). These are lifecycle ownership records, not a decision ledger. A second controller fails closed for alternate work while Main remains available. The child exits on IPC disconnect when its controller crashes, with its own bounded graceful shutdown. A restarted controller **does not adopt or signal** stale processes: absent identities are reconciled, exact live old identities are reported while awaiting self-exit, and unknown/reused/incomplete records are quarantined for operator reconciliation. The spawn-before-PID-record crash window deliberately sacrifices automatic availability rather than guess ownership or exceed the cap. If a recovery owner itself crashes mid-claim, operator reconciliation is also required. Never delete a quarantined record merely to bypass a resource conflict; independently prove the recorded child is gone first. Linux `/proc` access is required; unsupported/denied identity access disables alternate starts, not warm Main.

#### Navigation and durable interaction

`/preview/<id>/#<route>` preserves lane/session hashes entirely in the browser. Selecting Stopped requests an ID-only lazy start; opening a stopped deep link shows a retry/Main surface and does not implicitly launch on GET. The phone has the same lifecycle controls with touch targets and reserved layout space; no iframe is used. Failed start retains chat text and review composer/queued annotations in the same tab's stable-origin session storage. Annotation targets are revalidated by the existing revision-change flow before sending after a switch. Closing a tab is not durable receipt delivery. Local delivery-in-flight blocks selector navigation, and server leases protect delivery across other tabs. Receipt-confirmed notes use the existing stable gateway receipt store, not the disposable runtime's store.

Host-owned `/preview/<id>/api/review` preserves the separate `fm-agentos-review.v1` schema, original exact-origin/revision guards, region, route and batch IDs; server-derived provenance is written into the existing receipt. `/preview/<id>/api/chat` is a **separate** `fm-agentos-chat.v1` method; its injected `chatDeliver` adapter must explicitly address **primary Firstmate** before sends become available (otherwise 503, draft retained). Destination-agent fields are forbidden. This remains a transport integration gap, not a fabricated live chat connection.

Run `cd prototype && npm test` for automated lifecycle, gateway, ownership and UI coverage. `node prototype/scripts/preview-lifecycle-lab.mjs` from a clean committed disposable worktree provisions a task-local synthetic fixture under ignored `.preview-lab/` with a deliberate first-start port conflict, three-second synthetic chat delivery and an eight-second idle deadline. This operator-only script never runs from an HTTP route. Its tree-export provisioning also requires Python 3.10+ and Git 2.29+; see [history-free export and acceptance](HISTORY-FREE-EXPORT.md). Its `current.json` and `events.jsonl` bind acceptance to exact revision and owned child identities; use `chrome-devtools-axi` for browser operations and wait outside page execution contexts across navigation. Browser acceptance must bind to a clean exact revision and synthetic isolated loopback processes: warm Main → stopped alternate → Starting → Ready; select second → Busy if active → first Idling/Stopped → second Starting/Ready; failed start → warm Main → explicit retry/return. Check phone/desktop deep links and both draft types, then clean up only the exact owned children. Retain the evidence and exact promotion commits with the development branch; this is not authorization to promote Main.

## Migration inventory boundary

Preserved `fm/*` branches and isolated copies are source evidence, not automatic `dev/*` publications. See [the optional legacy inventory procedure](dev-branch-inventory.md) for mapping and collision checks; no installation inventory is shipped. No old source ref may be rewritten/deleted. A proposed `uat` set must list exact commits and evidence, not merely name a development branch.
